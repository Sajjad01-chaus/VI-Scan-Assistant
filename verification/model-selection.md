# Initial model selection

Historical experiment record, preserved 23 October 2026. Configuration defaults are recorded choices, not a current model catalog, allowance or availability guarantee. Later recovery, orchestration, quota handling and browser-fallback behavior are documented in [the current system design](../docs/system-design.md). The measurements below have not been rerun for the documentation refresh.

This is an exploratory engineering comparison using four clips generated by the Windows speech synthesizer. It does not establish clinical accuracy, performance on human accents/noise, sustained reliability, or account billing status. No real patient data was sent.

## Recommended defaults

- Live STT: Google `gemini-3.5-transcribe-live`.
- LLM: Groq `openai/gpt-oss-120b`.
- TTS: Groq `canopylabs/orpheus-v1-english` (voice `troy`) for English responses; Google `gemini-3.8-flash-lite-tts` as fallback. Selection is based on measured complete-audio latency, not a subjective voice-quality ranking.
- File STT fallback: Groq `whisper-large-v3`; preserve the audio and editable transcript. Turbo is a faster candidate for short commands, but omitted a clinically relevant correction marker in this sample.
- No-key reviewer mode: typed fixtures and deterministic tests, explicitly labeled.

## Measurements

Google live STT returned the four reference transcripts exactly, ignoring punctuation and capitalization. First partial text arrived 756-1273 ms after audio sending began. Final text arrived 368-460 ms after the final audio chunk was sent. WebSocket setup took 687-1179 ms. These numbers are separate from model-only latency and include network and harness behavior. Audio was paced by the test harness, not captured from a live microphone.

Groq Whisper Large v3 succeeded on 4/4 requests; median full-response latency after upload began was 2809 ms. It transcribed three clips exactly after normalization, but substituted `carries` for `caries` in the correction clip.

Groq Whisper Turbo succeeded on 4/4 requests; median full-response latency was 1822.5 ms. It transcribed three clips exactly after normalization, but omitted `Correction` in the correction clip. This could change how the downstream system resolves conflicting tooth sites.

Both Whisper models had one normalized word edit across 44 reference words (2.27% aggregate WER). Equal WER masks materially different error types. Four clips are too few to establish a general ranking. File-response times must not be compared directly with streaming finalization delay: the latter overlaps with speech delivery.

Groq GPT-OSS 120B returned parseable schema-constrained JSON in 3/3 extraction cases; median complete-response latency was 951 ms. 20B did so in 3/3 cases; median was 1050 ms. All six responses included clinician review and verbatim evidence. Manual inspection favored 120B's conservative unspecified site for the isolated fracture-negation sentence; 20B assigned it to the previously mentioned tooth. This is not a validated semantic-scoring result. The handling of `No definite caries` also needs a richer uncertainty representation and dedicated tests.

Google TTS succeeded on 3/3 requests with full-audio latencies of 3858, 3416, and 3209 ms (median 3416 ms). This is not time-to-first-playable-audio. Subjective naturalness and pronunciation have not been graded. Text should appear before speech is ready.

Groq Orpheus initially returned `model_terms_required`. After the user confirmed acceptance, it succeeded on 3/3 requests: 1712, 1530, and 2247 ms (median 1712 ms). The returned WAV headers used unknown-length size markers; playable copies were created with corrected container lengths while preserving PCM samples. Each clip contains about 2.88 seconds of speech. An automated Whisper Large v3 check recovered the intended sentence exactly from one sample; this is not a subjective quality evaluation.

Google file transcription returned HTTP 200 on three requests, but the harness did not parse a transcript. Those results are unscored. The fourth request and a diagnostic retry returned HTTP 503 high-demand errors. These file-endpoint results do not invalidate the separate successful streaming tests.

## Corrected TTS comparison

The initial Google request prefixed the sentence with `Say clearly:`. An automated content check showed that Google spoke those extra words, so the earlier Google timings are superseded for selection purposes. With the request corrected to contain only the intended sentence, three Google requests succeeded in 2633, 3042, and 2099 ms (median 2633 ms). A sample passed the same automated content check as Orpheus. Orpheus returned full audio about 35% sooner by median in these separate small runs. Google and Groq use different voices and speaking speeds; no general quality ranking or time-to-first-playable-audio claim follows. The runs were not simultaneous and may be affected by transient network/service conditions.

Final recommended chain: Google streaming STT -> Groq GPT-OSS 120B plus validated application tools -> Groq Orpheus English TTS. Groq Whisper Large v3 remains the file-STT fallback; Google TTS is the speech fallback.
